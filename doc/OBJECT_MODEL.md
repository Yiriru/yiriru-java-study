# 자동차 객체 관계와 역할

이 문서는 자동차 객체지향 실습에서 사용하는 객체들의 관계와 역할을 설명한다.
행동 규칙은 `TEST_CASES_SSOT.md`를 기준으로 하고, 이 문서는 그 규칙을 이해하기 위한 객체 모델 설명으로 사용한다.

나중에 SSOT를 확장할 때 이 문서의 내용도 기준 문서의 일부로 편입할 수 있다.

## 설계 방향

이 실습의 목표는 실제 자동차를 완전히 재현하는 것이 아니다.
자동차를 예제로 삼아 객체가 어떤 책임을 가지고, 서로 어떻게 협력하는지 배우는 것이다.

따라서 객체는 다음 기준으로 나눈다.

| 기준 | 설명 |
| --- | --- |
| 상태를 가진 대상 | `Car`, `Engine`, `Tire` |
| 운전자 입력을 표현하는 대상 | `Accel`, `Brake` |
| 출력 보조 도구 | `Print`, `Util` |
| 실행 시작점 | `App` |

## 객체 목록

| 객체 | 주 역할 | 주요 상태 |
| --- | --- | --- |
| `Car` | 자동차 전체 상태를 조율한다. | `speed`, `engine`, 타이어 4개 |
| `Engine` | 시동 상태를 표현한다. | `isRunning` |
| `Tire` | 타이어의 위치와 굴러감 상태를 표현한다. | `position`, `isRolling` |
| `TirePosition` | 타이어 위치 이름을 정의한다. | 없음 |
| `Accel` | 가속 페달 입력을 표현한다. | 조작 대상 `Car` |
| `Brake` | 브레이크 입력을 표현한다. | 조작 대상 `Car` |
| `Print` | 일반 로그와 에러 로그를 출력한다. | 없음 |
| `Util` | 한 줄 출력을 수행한다. | 없음 |
| `App` | 실행 예시 흐름을 구성한다. | 없음 |

## 소유 관계

자동차는 엔진과 타이어를 가진다.
이 관계는 자동차가 자기 구성 요소의 상태를 일관되게 관리한다는 뜻이다.

| 소유자 | 소유 대상 | 개수 |
| --- | --- | --- |
| `Car` | `Engine` | 1개 |
| `Car` | `Tire` | 4개 |

타이어 4개는 각각 다른 위치를 가진다.

| 필드 | 위치 |
| --- | --- |
| `frontLeftTire` | `FRONT_LEFT` |
| `frontRightTire` | `FRONT_RIGHT` |
| `backLeftTire` | `BACK_LEFT` |
| `backRightTire` | `BACK_RIGHT` |

## 의존 관계

가속 장치와 브레이크는 자동차를 조작하지만, 자동차의 부품을 직접 제어하지 않는다.

| 객체 | 의존 대상 | 이유 |
| --- | --- | --- |
| `Accel` | `Car` | 자동차에 가속 요청을 보내기 위해 |
| `Brake` | `Car` | 자동차에 감속 요청을 보내기 위해 |
| `Tire` | `Util` | 상태 변화 메시지를 출력하기 위해 |
| `Print` | `Util` | 로그 메시지를 출력하기 위해 |
| `App` | `Car`, `Accel`, `Brake`, `Print`, `Util` | 실행 예시를 구성하기 위해 |

## 책임 분리

자동차는 전체 상태의 일관성을 책임진다.
엔진, 속도, 타이어 상태가 서로 어긋나지 않도록 조율한다.

`Engine`은 시동 상태만 책임진다.
엔진이 켜져 있을 때 속도가 얼마나 증가하는지는 엔진이 아니라 자동차가 결정한다.

`Tire`는 자기 위치와 굴러감 상태만 책임진다.
자동차가 움직이는지 아닌지 판단하는 책임은 타이어에게 없다.

`Accel`은 운전자의 가속 입력만 표현한다.
가속 후 속도와 타이어 상태를 직접 바꾸지 않고, 자동차에 요청한다.

`Brake`는 운전자의 감속 입력만 표현한다.
브레이크 후 속도와 타이어 상태를 직접 바꾸지 않고, 자동차에 요청한다.

## 상태 관리 기준

자동차 상태의 최종 기준은 `Car`이다.

| 상태 | 최종 관리 책임 |
| --- | --- |
| 엔진 켜짐/꺼짐 | `Car`가 `Engine`에 요청한다. |
| 속도 | `Car`가 직접 관리한다. |
| 타이어 굴러감 상태 | `Car`가 속도에 맞춰 갱신한다. |
| 타이어 위치 | `Tire`가 가지고 있고 생성 시 정해진다. |

속도와 타이어 상태는 함께 움직여야 한다.

| 자동차 속도 | 타이어 상태 |
| --- | --- |
| `0` | 모든 타이어가 멈춤 |
| `0`보다 큼 | 모든 타이어가 굴러감 |

## 메시지 흐름

### 엔진 켜기

1. 외부에서 `Car.startEngine()`을 호출한다.
2. `Car`는 자기 엔진에게 `start()`를 요청한다.
3. `Engine`의 `isRunning` 값이 `true`가 된다.

### 엔진이 켜진 상태에서 가속

1. 외부에서 `Accel.press()`를 호출한다.
2. `Accel`은 `Car.accelerate()`를 호출한다.
3. `Car`는 엔진이 켜져 있는지 확인한다.
4. 엔진이 켜져 있으면 `speed`를 `10` 증가시킨다.
5. `Car`는 속도가 `0`보다 크므로 타이어 4개를 굴러가는 상태로 바꾼다.

### 엔진이 꺼진 상태에서 가속

1. 외부에서 `Accel.press()`를 호출한다.
2. `Accel`은 `Car.accelerate()`를 호출한다.
3. `Car`는 엔진이 꺼져 있음을 확인한다.
4. `speed`는 변하지 않는다.
5. 타이어 상태도 변하지 않는다.

### 브레이크

1. 외부에서 `Brake.press()`를 호출한다.
2. `Brake`는 `Car.brake()`를 호출한다.
3. `Car`는 `speed`를 `10` 감소시킨다.
4. 속도는 `0`보다 작아질 수 없다.
5. 감소 후 속도가 `0`이면 타이어 4개를 멈춘 상태로 바꾼다.
6. 감소 후 속도가 `0`보다 크면 타이어 4개는 굴러가는 상태를 유지한다.

## 객체 관계 요약

```text
App
 ├─ creates Car
 │   ├─ owns Engine
 │   ├─ owns Tire(FRONT_LEFT)
 │   ├─ owns Tire(FRONT_RIGHT)
 │   ├─ owns Tire(BACK_LEFT)
 │   └─ owns Tire(BACK_RIGHT)
 ├─ creates Accel -> requests Car.accelerate()
 ├─ creates Brake -> requests Car.brake()
 └─ uses Print / Util for observable output
```

## 현재 모델의 의도적인 단순화

아래 내용은 실제 자동차와 다르지만, 이번 실습에서는 단순하게 둔다.

| 단순화 | 이유 |
| --- | --- |
| 엔진은 켜짐/꺼짐만 가진다. | RPM, 연료, 출력까지 다루면 복잡도가 크게 올라간다. |
| 가속은 항상 속도 `10` 증가이다. | 입력 강도와 시간 개념을 아직 다루지 않는다. |
| 브레이크는 항상 속도 `10` 감소이다. | 감속 물리 모델을 아직 다루지 않는다. |
| 타이어는 바퀴 역할까지 함께 한다. | 바퀴와 타이어를 분리하면 객체 수가 늘어난다. |
| 모든 타이어는 같은 상태로 움직인다. | 전륜, 후륜, 사륜 구동 차이를 아직 다루지 않는다. |
