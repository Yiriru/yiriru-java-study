# 자동차 객체 모델 SSOT

이 문서는 자동차 객체지향 실습의 기준 문서이다.
프로그램 코드와 테스트 코드는 이 문서에 적힌 사실을 기준으로 작성한다.

목표는 실제 자동차를 전부 구현하는 것이 아니다.
자동차라는 익숙한 대상을 이용해서 객체, 책임, 상태, 협력 관계를 배우는 것이다.

## 현재 추상화 수준

실제 자동차는 엔진, 변속기, 조향 장치, 서스펜션, 연료, 전기 장치 등으로 이루어진 매우 복잡한 개체이다.
현재 실습에서는 그중 일부만 단순화해서 다룬다.

이번 단계에서 다루는 범위는 다음과 같다.

| 영역 | 이번 단계에서 다루는 내용 |
| --- | --- |
| 자동차 | 엔진 1개와 타이어 4개를 가지고 있고, 현재 속도를 가진다. |
| 엔진 | 켜져 있는지 꺼져 있는지 상태를 가진다. |
| 타이어 | 굴러가는 상태인지 멈춘 상태인지 가진다. |
| 가속 | 자동차의 속도를 증가시킨다. |
| 브레이크 | 자동차의 속도를 감소시킨다. |
| 출력 | 학습자가 상태 변화를 관찰할 수 있게 콘솔에 메시지를 남긴다. |

이번 단계에서 다루지 않는 내용은 다음과 같다.

| 영역 | 제외 이유 |
| --- | --- |
| 엔진 내부 동작 | 이번 단계에서는 켜짐/꺼짐 상태만 다룬다. 연료, 폭발, 동력 전달까지 들어가면 학습 범위가 커진다. |
| 변속기 | 속도와 기어비의 관계는 다음 단계에서 다룰 수 있다. |
| 조향 장치 | 방향 전환은 현재 가속/정지 실습과 별도 주제이다. |
| 바퀴와 타이어의 분리 | 지금은 타이어가 바퀴 역할까지 함께 담당한다고 본다. |
| 도로 상태와 마찰 | 물리 시뮬레이션은 하지 않는다. |

## 핵심 객체와 책임

각 객체는 자기 책임을 작게 가져야 한다.
한 객체가 모든 일을 직접 처리하지 않고, 필요한 객체들과 협력해야 한다.

| 객체 | 책임 |
| --- | --- |
| 자동차 | 전체 상태를 관리한다. 엔진, 속도, 타이어 상태를 일관되게 유지한다. |
| 엔진 | 시동이 켜져 있는지 꺼져 있는지 상태를 가진다. |
| 타이어 | 자신의 위치와 굴러가는 상태를 가진다. |
| 가속 장치 | 운전자의 가속 입력을 표현한다. 자동차의 속도를 올리는 요청을 한다. |
| 브레이크 | 운전자의 감속 입력을 표현한다. 자동차의 속도를 낮추는 요청을 한다. |
| 출력 도구 | 상태 변화나 로그를 콘솔에 출력한다. |

## 코드 구조 규칙

하나의 최상위 클래스, interface, enum은 하나의 파일에만 둔다.
파일 이름은 그 안에 들어 있는 최상위 타입 이름과 같아야 한다.

예를 들어 `Car`는 `Car.java`, `Engine`은 `Engine.java`, `Tire`는 `Tire.java`, `TirePosition`은 `TirePosition.java`에 둔다.
`App.java`에는 애플리케이션 실행 시작점인 `App`만 둔다.

이 규칙은 객체의 책임을 파일 구조에서도 분리해서 보기 쉽게 만들기 위한 것이다.
새 객체를 추가할 때도 같은 기준을 따른다.

## 자동차의 기본 상태

새 자동차는 정지 상태로 시작한다.

새 자동차가 만들어지면 다음 사실이 성립해야 한다.

| 사실 | 기대 값 |
| --- | --- |
| 엔진 상태 | 꺼짐 |
| 현재 속도 | `0` |
| 앞쪽 왼쪽 타이어 | 멈춤 |
| 앞쪽 오른쪽 타이어 | 멈춤 |
| 뒤쪽 왼쪽 타이어 | 멈춤 |
| 뒤쪽 오른쪽 타이어 | 멈춤 |

자동차의 속도는 음수가 될 수 없다.
속도가 `0`이면 자동차는 정지 상태이다.
속도가 `0`보다 크면 자동차는 움직이는 상태이다.

## 엔진 규칙

엔진은 자동차가 움직이기 위한 동력 준비 상태를 표현한다.
이번 단계에서는 엔진 내부 동작은 다루지 않고, 켜짐/꺼짐 상태만 다룬다.

새 엔진은 꺼진 상태로 시작한다.

| 상황 | 기대 결과 |
| --- | --- |
| 새 엔진을 만든다. | 엔진은 꺼져 있다. |
| 엔진을 켠다. | 엔진 상태가 켜짐이 된다. |
| 엔진을 끈다. | 엔진 상태가 꺼짐이 된다. |

자동차는 자신의 엔진을 가진다.
새 자동차의 엔진은 꺼져 있어야 한다.
자동차는 엔진을 켜거나 끄는 요청을 받을 수 있다.

## 타이어 규칙

자동차는 정확히 4개의 타이어를 가진다.

타이어 위치는 다음 네 가지로 구분한다.

| 위치 | 의미 |
| --- | --- |
| 앞쪽 왼쪽 | 운전석 기준 앞쪽 왼쪽 타이어 |
| 앞쪽 오른쪽 | 운전석 기준 앞쪽 오른쪽 타이어 |
| 뒤쪽 왼쪽 | 운전석 기준 뒤쪽 왼쪽 타이어 |
| 뒤쪽 오른쪽 | 운전석 기준 뒤쪽 오른쪽 타이어 |

타이어의 굴러감 상태는 자동차의 움직임과 일치해야 한다.

| 자동차 상태 | 타이어 상태 |
| --- | --- |
| 속도가 `0`이다. | 모든 타이어가 멈춰 있어야 한다. |
| 속도가 `0`보다 크다. | 모든 타이어가 굴러가야 한다. |

타이어는 자기 상태를 가질 수 있지만, 최종적인 상태 일관성은 자동차가 관리한다.

## 가속 규칙

가속은 자동차를 더 빠르게 움직이게 하는 운전자 입력이다.

이번 단계에서는 가속 장치를 한 번 누르면 자동차 속도가 `10` 증가한다고 본다.

| 상황 | 기대 결과 |
| --- | --- |
| 엔진이 꺼진 상태에서 가속한다. | 속도는 변하지 않는다. |
| 엔진이 꺼진 상태에서 가속한다. | 모든 타이어는 멈춰 있어야 한다. |
| 엔진을 켠 뒤 정지 상태에서 가속한다. | 속도가 `10`이 된다. |
| 속도 `10`에서 다시 가속한다. | 속도가 `20`이 된다. |
| 가속 후 속도가 `0`보다 크다. | 모든 타이어가 굴러간다. |

가속 장치는 타이어를 직접 굴리는 객체가 아니다.
가속 장치는 자동차에 가속 요청을 하고, 자동차가 속도와 타이어 상태를 함께 갱신한다.
자동차는 엔진이 켜져 있을 때만 가속 요청을 속도 증가로 반영한다.

## 브레이크 규칙

브레이크는 자동차를 느리게 하거나 멈추게 하는 운전자 입력이다.

이번 단계에서는 브레이크를 한 번 누르면 자동차 속도가 `10` 감소한다고 본다.
브레이크를 눌러도 속도는 `0`보다 작아질 수 없다.

| 상황 | 기대 결과 |
| --- | --- |
| 속도 `20`에서 브레이크를 누른다. | 속도가 `10`이 된다. |
| 속도 `10`에서 브레이크를 누른다. | 속도가 `0`이 된다. |
| 속도 `0`에서 브레이크를 누른다. | 속도는 계속 `0`이다. |
| 브레이크 후 속도가 `0`이다. | 모든 타이어가 멈춘다. |
| 브레이크 후 속도가 `0`보다 크다. | 모든 타이어는 계속 굴러간다. |

브레이크도 타이어를 직접 멈추는 객체가 아니다.
브레이크는 자동차에 감속 요청을 하고, 자동차가 속도와 타이어 상태를 함께 갱신한다.

## 출력 규칙

출력은 자동차의 핵심 동작이 아니라 학습자가 상태 변화를 관찰하기 위한 보조 수단이다.
따라서 핵심 테스트는 먼저 상태를 검증하고, 출력은 필요한 경우에만 함께 검증한다.

모든 출력은 `System.out`으로 한 줄씩 출력한다.
각 출력 줄은 시스템 기본 줄바꿈으로 끝난다.

일반 로그는 전달받은 문장을 그대로 출력한다.

| 입력 | 기대 출력 |
| --- | --- |
| `Hello` | `Hello` |

에러 로그는 전달받은 문장 앞에 `ERROR: `를 붙여 출력한다.

| 입력 | 기대 출력 |
| --- | --- |
| `Something failed` | `ERROR: Something failed` |

## 전체 실행 흐름

애플리케이션을 실행하면 하나의 자동차를 만들고, 운전자가 조작하는 흐름을 보여준다.

기본 실행 흐름은 다음과 같다.

1. 자동차를 만든다.
2. 자동차의 초기 상태가 엔진 꺼짐, 속도 `0`, 타이어 정지 상태임을 확인할 수 있어야 한다.
3. 엔진을 켠다.
4. 가속 장치를 눌러 자동차를 움직이게 한다.
5. 자동차의 속도가 증가하고 타이어가 굴러가는 상태가 되어야 한다.
6. 브레이크를 눌러 자동차를 감속시킨다.
7. 속도가 `0`이 되면 자동차는 정지하고 모든 타이어가 멈춰야 한다.

전체 실행 흐름은 세부 구현을 모두 검증하기보다는 주요 상태 변화가 연결되어 있는지 확인하는 용도로 둔다.

## 테스트 케이스 작성 기준

테스트는 코드 구조가 아니라 이 문서의 사실을 검증해야 한다.
테스트 코드가 없어도 이 문서를 보고 같은 테스트를 다시 만들 수 있어야 한다.

권장 테스트 단위는 다음과 같다.

| 테스트 대상 | 검증할 사실 |
| --- | --- |
| 자동차 초기 상태 | 엔진 꺼짐, 속도 `0`, 타이어 4개 모두 멈춤 |
| 엔진 | 새 엔진은 꺼짐, 켜기, 끄기 |
| 타이어 | 위치를 가진다, 굴러감 상태를 표현할 수 있다 |
| 엔진 꺼짐 상태의 가속 | 속도 변화 없음, 타이어 4개 모두 멈춤 |
| 가속 | 엔진 켜짐 상태에서 1회 가속 시 속도 `10` 증가, 타이어 4개 굴러감 |
| 반복 가속 | 가속할 때마다 속도가 `10`씩 증가 |
| 브레이크 | 1회 브레이크 시 속도 `10` 감소 |
| 정지 | 속도가 `0`이 되면 타이어 4개 모두 멈춤 |
| 정지 상태 브레이크 | 속도는 음수가 되지 않고 `0`으로 유지 |
| 출력 | 일반 로그와 에러 로그 형식 |
| 전체 실행 | 자동차 생성, 가속, 감속, 정지 흐름이 연결됨 |

출력이 있는 동작은 콘솔에 직접 흘려보내지 말고 캡처해서 검증한다.
